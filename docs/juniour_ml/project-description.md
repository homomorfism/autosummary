## Постановка задачи

У студента, прослушавшего лекцию, нет надёжного способа повторить материал и проверить, действительно ли он его понял. Курс оставляет после себя два артефакта, и оба неполноценны: слайды теряют всё, что лектор только *произнёс* (разобранные примеры, оговорки, интуицию, акценты вида «это будет на экзамене»), а полная видеозапись длится 2–3,5 часа, и пересматривать её перед экзаменом непрактично.

Проект строит и — что важнее — *измеряет* пайплайн, который превращает видеозапись лекции и слайды в:

1. **обоснованный структурированный конспект**, объединяющий устную речь лектора со слайдами, где каждое утверждение помечено источником (`slide` / `transcript` / `both`);
2. **адаптивный квиз для самопроверки**, вопросы которого автоматически отбраковываются и перегенерируются на основе измеренного психометрического качества (сложность, дискриминативность) по ответам реальных студентов.

Центральный исследовательский вопрос — оценочный, а не только генеративный: **можно ли численно доказать, что мультиисточниковый конспект содержательно богаче, чем одни слайды, и что его содержание достоверно относительно источников?** Ключевая метрика работы — *transcript-only coverage*: доля фактов, которые лектор произнёс, но которых нет на слайдах, и которые сохранились в конспекте. Для конспекта, построенного только по слайдам, эта метрика по определению равна 0 %.

Работа структурирована тремя экспериментами:

- **E1 — оценка конспекта на уровне утверждений (claims):** покрытие (recall), достоверность (precision) и F1 конспекта относительно обоих источников, измеренные по атомарным фактам, а не по поверхностному пересечению текста.
- **E2 — бенчмарк STT-провайдеров:** локальный whisper.cpp против Google Cloud STT по word error rate (WER), term error rate (TER) на доменных терминах, задержке и стоимости.
- **E3 — психометрика вопросов:** классический item analysis (сложность p, точечно-бисериальная дискриминативность r_pb) по записанным попыткам прохождения квизов, с правилом отбраковки и замкнутым циклом LLM-регенерации.

## Актуальность

- **Кому это нужно.** Студентам технических программ при подготовке к экзаменам и пересдачам — всем, кому нужно повторить 20+ часов видеолекций за дни, а не недели. Тот же пайплайн применим к корпоративным обучающим записям, докладам конференций и архивам MOOC-курсов.
- **Почему важен устный канал.** В курсе, использованном как датасет, восстановленное устное содержание одной лекции содержит сотни атомарных фактов, отсутствующих на слайдах (334 transcript-only утверждения из 526 для лекции 6). Инструменты, суммаризирующие только слайды — или только аудио — молча отбрасывают один из двух источников. Проект рассматривает «сказанное, но не показанное на слайдах» как ценность, которую нужно сохранить и измерить.
- **Почему сейчас.** LLM с длинным контекстом и структурированным выводом делают мультиисточниковую обоснованную суммаризацию практичной, а локальный STT (whisper.cpp) делает транскрибацию бесплатной и приватной. Чего по-прежнему не хватает — и в чём вклад этой работы — это *оценка*: n-граммные метрики вроде ROUGE не показывают, пережил ли факт суммаризацию, а LLM-конспектам нужны гарантии достоверности, прежде чем студенты смогут им доверять. Оценка на уровне утверждений с откалиброванным LLM-судьёй решает именно эту задачу.
- **Не только конспекты.** Пассивное чтение — слабый обучающий сигнал. Слой квизов замыкает цикл, а его психометрический фильтр устраняет реальную слабость LLM-генерируемых вопросов: многие из них тривиально просты или не различают студентов, понявших лекцию, и не понявших её.

## Вход и выход

**Вход:**

- **Видеозапись лекции** — MP4, H.264, 1920×1080 @ 60 fps, 1,5–3,5 часа на лекцию (датасет — ≈ 21,3 часа по 9 лекциям). Используется только аудиодорожка: она извлекается ffmpeg в 16 кГц моно PCM WAV — единый входной формат для обоих STT-провайдеров, что делает качество распознавания сравнимым.
- **Слайды** — текстовый PDF (LaTeX/beamer), 21–87 страниц на лекцию (всего 619 страниц по курсу). Текст извлекается постранично через pypdf; сканированные/растровые презентации вне рамок работы (OCR не используется).

**Выход:**

- конспект — структурированный конспект: Markdown с LaTeX-математикой, каждое утверждение помечено источником (`slide` / `transcript` / `both`); ~3 200 слов для лекции 6.
- квиз — 5 вопросов с одним верным вариантом; pydantic-схема гарантирует ровно один правильный вариант на вопрос; каждый вариант снабжён объяснением.
- **Веб-приложение** (Next.js): курс → лекция → конспект → квиз → результаты → статистика вопросов; попытки сохраняются в SQLite с идентификатором вопроса на основе контентного хэша.

## Метрики

**E1 — качество конспекта (уровень утверждений).** Все три текста (восстановленные слайды, восстановленный транскрипт, конспект) декомпозируются LLM в атомарные самодостаточные утверждения, каждое с меткой значимости (`core` / `supporting` / `aside`). Единый механизм проверки следования (entailment) — top-k поиск по эмбеддингам с последующим строгим батчевым NLI-решением LLM-судьи — запускается в трёх направлениях:

| метрика | определение |
|---|---|
| **Coverage** (recall) | доля утверждений источников (слайды + транскрипт), следующих из конспекта; также отдельно по источникам и по `core`-утверждениям |
| **Faithfulness** (precision) | доля утверждений конспекта, следующих из источников (1 − доля галлюцинаций/искажений) |
| **F1** | гармоническое среднее coverage и faithfulness |
| **Transcript-only coverage** | из устных утверждений, *не* следующих из слайдов, — доля сохранённых в конспекте; тезис «конспект > слайды» одним числом |

Поскольку судья — сам LLM, его вердикты валидируются против ручной разметки до того, как метрикам можно доверять (см. Валидацию). Достигнуто на девелоперской лекции: coverage 62,5 %, faithfulness 86,5 %, F1 72,6 %, transcript-only coverage 48,5 %; целевые значения для остальных лекций — F1 ≥ 70 % и faithfulness ≥ 85 %, достижимость которых показана результатами разработки.

**E2 — качество STT.** **WER** (word error rate) относительно вручную транскрибированного «золотого» фрагмента; **TER** (term error rate) — доля доменных терминов, собранных со слайдов, отсутствующих в транскрипте при нечётком сопоставлении (измеряется без ручной разметки); плюс задержка и стоимость за час аудио. Достигнуто: WER 2,3 % (whisper.cpp large) против 16,3 % (Google STT) на золотом наборе.

**E3 — качество вопросов (классическая теория тестов).** По каждому вопросу: **сложность** p — доля верных ответов; **дискриминативность** r_pb — точечно-бисериальная корреляция между верным ответом на вопрос и *rest score* (суммарный балл без этого вопроса). Правило отбраковки (при ≥ 5 попытках): вопрос изымается, если p ∉ [0,30; 0,85] или r_pb < 0,15; изъятые вопросы архивируются и перегенерируются LLM с учётом их измеренной статистики и направления ошибок. Критерий успеха: после одного цикла «отбраковка–регенерация» доля вопросов в целевом диапазоне сложности растёт. Достигнуто на собранных попытках (49 попыток, 5–6 на квиз): 33/45 вопросов (73 %) проходят правило отбраковки; при 5–6 попытках на вопрос оценки шумные — результатом является работающая методология и замкнутый цикл, с явно проговорённой оговоркой о размере выборки.

## Валидация

В пайплайне нет обучаемой модели (все обучаемые компоненты — замороженные предобученные модели), поэтому валидация направлена на *измерения*, а не на train/test-разбиение:

- **Калибровка LLM-судьи (E1).** Вердикты судьи проверены на 40 вручную размеченных парах, стратифицированных по трём направлениям проверки: согласие 39/40 (97,5 %), каппа Коэна κ = 0,95, **ноль ложноположительных** и одно ложноотрицательное решение. Ноль FP означает, что faithfulness не завышена снисходительностью судьи; единичный FN означает, что метрики типа coverage слегка консервативны. При n = 40 95 %-й доверительный интервал согласия — примерно 87–100 %, поэтому результат заявляется как «κ ≈ 0,95 на выборке из 40 пар», а рекалибровка повторяется после любого изменения промпта или модели судьи.
- **Разбиение development / held-out по лекциям (E1).** Пайплайн (промпты, ретривер, top-k, стадия реконструкции) итерировался только на лекции 6. Финальная конфигурация без изменений запускается на остальных 8 лекциях, которые служат отложенным набором; результаты приводятся по лекциям и агрегированно.
- **Золотой эталон (E2).** WER/TER считаются относительно вручную транскрибированного 19,5-минутного фрагмента; аудио для обоих провайдеров идентично (одинаковое извлечение ffmpeg 16 кГц моно), так что сравнение изолирует именно распознаватель.
- **Гарантии психометрики (E3).** Статистики считаются только по вопросам с ≥ 5 ответами; дискриминативность использует rest score (вклад самого вопроса исключён) во избежание автокорреляции; оговорка о выборке (5–6 ответов на вопрос: шаг p — 0,17–0,20, один респондент сдвигает r_pb на ±0,5) сопровождает каждую оценку.

## Эксперименты

### Бейзлайн

Бейзлайн — первый работающий end-to-end пайплайн, намеренно простой в каждом компоненте:

- **Конспект:** генерируется напрямую из **сырого ASR-транскрипта** (46k слов, с филлерами, вопросами из зала и оффтопом) + извлечённого текста слайдов.
- **Оценка:** декомпозиция на утверждения без меток значимости; поиск с `all-MiniLM-L6-v2`, top-k = 8; судья `deepseek-v4-pro`.
- **STT-точка отсчёта:** Google Cloud STT (облачное long-running распознавание) против whisper.cpp на золотом наборе.
- **Концептуальная точка отсчёта:** конспект только по слайдам, который по построению даёт 0 % transcript-only coverage.

#### Метрики и результаты бейзлайна

Лекция 6 (девелоперская), транскрипт whisper.cpp:

| метрика | бейзлайн |
|---|---|
| coverage | 53,9 % |
| coverage: слайды / транскрипт | 70,9 % / 48,8 % |
| faithfulness | 69,4 % |
| F1 | 60,7 % |
| transcript-only сохранено | 37,2 % (из 349 утверждений) |

Золотой STT-набор (19,5 мин, лекция 6): **whisper.cpp WER 2,3 %** против **Google STT WER 16,3 %** (TER даёт тот же порядок) — whisper.cpp выбран умолчанием пайплайна; он к тому же бесплатен и локален.

### Основная модель

Основной пайплайн сохраняет тот же каркас и усиливает стадии, которые бейзлайн показал узким местом (шум ASR загрязняет и конспект, и само измерение):

1. **Реконструкция транскрипта** — новая LLM-стадия, превращающая сырой ASR в чистый текст лекции: удаляет филлеры/вопросы/административное/оффтоп, исправляет ошибки распознавания, записывает устную математику в LaTeX. 46k → 8,6k слов на лекции 6 при *росте* числа извлекаемых атомарных утверждений (526 против 449) и без сокращения пула transcript-only (334 против 294) — свидетельство того, что сжатие является чисткой, а не скрытой суммаризацией.
2. **Перегенерация конспекта** из восстановленного транскрипта + восстановленных слайдов (structured-output вызов LLM; разметка источников гарантируется pydantic-схемой).
3. **Улучшения оценки** — метки значимости (`core`/`supporting`/`aside`) при декомпозиции; ретривер `BAAI/bge-small-en-v1.5`; top-k = 16, чтобы составные утверждения собирали все свои посылки. Все стадии кэшируются с ключом по отпечатку настроек.
4. **Слой квизов (E3)** — генерация квиза из конспекта, сбор попыток через веб-приложение, item analysis (p, r_pb относительно rest score), правило отбраковки и LLM-регенерация с учётом измеренной статистики.

#### Метрики и результаты E3 (item analysis по production-попыткам)

| 08 | 6 | 2,5 | 0,50 | +0,64 | 5/5 | — |

Три квиза (лекции 04, 08, 09) полностью чистые; каждый квиз сохраняет минимум 2 пригодных вопроса. 12 отбракованных вопросов распадаются на три типа отказа:

- **Слишком лёгкие (2):** p = 1,00, все респонденты отвечают верно, r_pb не определена (нет дисперсии) — вопросы «на факт, который помнят все» (зачем нужна нелинейность; как skip-connection в ResNet помогает градиентам). Нулевая измерительная ценность, первые кандидаты на регенерацию в более тонкий зонд той же темы.
- **Слишком трудные (4):** p = 0,20 (1 из 5). Важный нюанс: два вопроса лекции 7 (DETR без NMS, deformable attention) при этом имеют **r_pb = +0,71** — верно отвечает именно сильнейший респондент, а 3 из 5 сходятся на *одном и том же* дистракторе. Это либо действительно притягательное заблуждение, либо спорный ключ ответа — перед механической регенерацией нужна ручная проверка ключа. Оставшиеся два трудных вопроса проваливаются по обеим осям (r_pb ≈ 0 и −0,13).
- **Низкая дискриминативность (6):** умеренная-высокая p (0,40–0,83) при r_pb от −0,69 до −0,08. Доминирующий на такой выборке паттерн: 4 из 5 отвечают верно, а единственный промах принадлежит *сильному* респонденту, что резко уводит r_pb в минус. Худший квиз по этой оси — лекция 3 (3 из 5 вопросов не разделяют понявших и не понявших).

## Репозиторий

https://github.com/homomorfism/autosummary — Python (uv), пакет `app/` со стадиями пайплайна как CLI-модулями, `docs/experiments/` с описаниями экспериментов, `data/` с собранным курсом, золотым набором и кэшированными артефактами оценки.

## Использование

Конечный продукт — **веб-приложение курса** для студентов: любая лекция с готовым конспектом появляется автоматически; студент открывает лекцию, читает конспект (серверный рендеринг Markdown с KaTeX для LaTeX), проходит квиз из 5 вопросов и видит результат; каждая попытка пополняет статистику вопросов E3 на странице статистики лекции, которая, в свою очередь, управляет отбраковкой и регенерацией вопросов — квиз улучшается по мере того, как им пользуется больше студентов.

Преподаватели (авторы контента) запускают пайплайн по каждой лекции: транскрибация (whisper.cpp / Google STT) → реконструкция транскрипта → генерация конспекта → генерация квиза → психометрика с замкнутым циклом регенерации.
