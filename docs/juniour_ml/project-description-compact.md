# Lecture Autosummary: обоснованные мультиисточниковые конспекты лекций с адаптивной проверкой понимания

**Автор: Шамиль Арсланов**

## Постановка задачи

После лекции у студента остаются два неполноценных артефакта: слайды теряют всё, что лектор только *произнёс* (примеры, интуицию, акценты «это будет на экзамене»), а пересматривать видеозапись длиной 2–3,5 часа перед экзаменом непрактично.

Проект строит и — что важнее — *измеряет* пайплайн, превращающий видеозапись и слайды в:

1. **обоснованный структурированный конспект**, где каждое утверждение помечено источником (`slide` / `transcript` / `both`);
2. **адаптивный квиз для самопроверки**, вопросы которого отбраковываются и перегенерируются по измеренному психометрическому качеству на ответах реальных студентов.

Центральный исследовательский вопрос — оценочный: **можно ли численно доказать, что мультиисточниковый конспект содержательно богаче одних слайдов и достоверен относительно источников?** Ключевая метрика — *transcript-only coverage*: доля фактов, произнесённых лектором, отсутствующих на слайдах и сохранённых в конспекте (для конспекта только по слайдам она по определению 0 %).

Три эксперимента:

- **E1 — оценка конспекта на уровне утверждений:** coverage (recall), faithfulness (precision) и F1 по атомарным фактам, а не поверхностному пересечению текста.
- **E2 — бенчмарк STT:** whisper.cpp против Google Cloud STT по WER, TER на доменных терминах, задержке и стоимости.
- **E3 — психометрика вопросов:** item analysis (сложность p, дискриминативность r_pb) по записанным попыткам, с правилом отбраковки и замкнутым циклом LLM-регенерации.

## Актуальность

- **Кому нужно.** Студентам технических программ, которым надо повторить 20+ часов видеолекций за дни; пайплайн применим и к корпоративным записям, и к MOOC-архивам.
- **Почему устный канал важен.** Устное содержание одной лекции содержит сотни атомарных фактов, отсутствующих на слайдах (334 transcript-only утверждения из 526 для лекции 6); инструменты «только слайды» или «только аудио» молча отбрасывают один источник.
- **Почему сейчас.** LLM делают такую суммаризацию практичной, whisper.cpp — бесплатной и приватной. Не хватает *оценки*: ROUGE не показывает, пережил ли факт суммаризацию; вклад работы — claim-level оценка с откалиброванным LLM-судьёй.
- **Не только конспекты.** Психометрический фильтр квизов устраняет слабость LLM-вопросов: многие тривиальны или не различают понявших и не понявших.

## Вход и выход

**Вход:** видеозапись лекции (MP4, 1,5–3,5 ч; датасет ≈ 21,3 ч по 9 лекциям) — используется только аудио, извлекаемое ffmpeg в 16 кГц моно WAV, единый формат для обоих STT-провайдеров; слайды — текстовый beamer-PDF (21–87 стр., всего 619), текст извлекается pypdf, OCR вне рамок.

**Выход:** конспект (Markdown с LaTeX, каждое утверждение с меткой источника; ~3 200 слов для лекции 6); квиз из 5 вопросов с одним верным вариантом и объяснениями (pydantic-схема гарантирует ровно один верный); веб-приложение (Next.js): курс → конспект → квиз → результаты → статистика, попытки в SQLite с контентным хэшом вопроса.

## Метрики

**E1 — качество конспекта.** Слайды, транскрипт и конспект LLM-декомпозируются в атомарные утверждения с меткой значимости (`core`/`supporting`/`aside`). Единый механизм entailment (top-k поиск по эмбеддингам + строгий батчевый LLM-судья) даёт: **coverage** — доля утверждений источников, следующих из конспекта; **faithfulness** — доля утверждений конспекта, следующих из источников; **F1**; **transcript-only coverage** — доля сохранённых устных утверждений, не следующих из слайдов («конспект > слайды» одним числом). Судья валидируется против ручной разметки. Достигнуто на девелоперской лекции: coverage 62,5 %, faithfulness 86,5 %, F1 72,6 %, transcript-only 48,5 %; цели для остальных лекций — F1 ≥ 70 %, faithfulness ≥ 85 %.

**E2 — качество STT.** WER относительно вручную транскрибированного «золотого» фрагмента; TER — доля доменных терминов со слайдов, отсутствующих в транскрипте; задержка и стоимость за час аудио. Достигнуто: WER 2,3 % (whisper.cpp large) против 16,3 % (Google STT).

**E3 — качество вопросов.** По каждому вопросу: сложность p (доля верных ответов) и дискриминативность r_pb (точечно-бисериальная корреляция с *rest score* — баллом без этого вопроса). Отбраковка при ≥ 5 попытках: p ∉ [0,30; 0,85] или r_pb < 0,15; изъятые вопросы перегенерируются LLM с учётом статистики (результаты — ниже, в Экспериментах).

## Данные

Датасет — реальный курс **«Deep Learning and Computer Vision» (Harbour Space, 2026, лектор Сергей Николенко)**, собранный автором с публичной страницы курса:

- **9 лекций**: видео (MP4, 1080p; 1 ч 28 мин – 3 ч 30 мин; всего ≈ 21,3 ч) + beamer-PDF (21–87 стр., всего 619). Темы от классического ML до трансформеров и диффузионных моделей — плотная математика, нагружающая и STT, и суммаризацию.
- **Золотой STT-набор:** 19,5-минутный фрагмент лекции 6, вручную транскрибированный (~2 600 слов), с выходами обоих провайдеров.
- **Калибровка судьи:** 40 вручную размеченных пар (утверждение, посылки), стратифицированных по трём направлениям проверки.
- **Попытки квизов:** 49 попыток от 8 респондентов по всем 9 квизам; каждый из 45 вопросов достигает порога ≥ 5 ответов; баллы покрывают весь диапазон 0–5 (среднее 3,06, SD 1,54). Малое n — заявленное ограничение E3.
- **Особенности:** английская речь с акцентом и тяжёлой терминологией (бьёт по Google STT), beamer-overlay-дублирование слайдов, у лекции 4 аномально короткая презентация — ожидается межлекционная дисперсия.

Ссылки: страница курса — https://www.sergeynikolenko.ru/en/courses/harbourbcn26; датасет и разметка — в `data/` репозитория https://github.com/homomorfism/autosummary.

## Валидация

Обучаемой модели в пайплайне нет, поэтому валидируются *измерения*:

- **Калибровка судьи (E1):** согласие с ручной разметкой 39/40 (97,5 %), κ = 0,95, ноль ложноположительных (faithfulness не завышена) и одно ложноотрицательное (coverage слегка консервативна); при n = 40 результат заявляется как «κ ≈ 0,95 на 40 парах», рекалибровка — после любого изменения промпта или судьи.
- **Development / held-out по лекциям (E1):** пайплайн итерировался только на лекции 6; финальная конфигурация без изменений запускается на остальных 8 лекциях.
- **Золотой эталон (E2):** идентичное аудио для обоих провайдеров изолирует именно распознаватель.
- **Гарантии E3:** только вопросы с ≥ 5 ответами; rest score против автокорреляции; оговорка о шуме (один респондент сдвигает r_pb на ±0,5) сопровождает каждую оценку.

## Эксперименты

### Бейзлайн

Первый end-to-end пайплайн, намеренно простой: конспект напрямую из **сырого ASR-транскрипта** (46k слов, с филлерами и оффтопом) + текста слайдов; декомпозиция без меток значимости, ретривер `all-MiniLM-L6-v2` (top-k = 8), судья `deepseek-v4-pro`; Google STT против whisper.cpp на золотом наборе; концептуальная точка отсчёта — конспект только по слайдам (0 % transcript-only coverage).

Результаты (лекция 6): coverage 53,9 %, faithfulness 69,4 %, F1 60,7 %, transcript-only 37,2 %. Золотой набор: **whisper.cpp WER 2,3 %** против **Google STT 16,3 %** — whisper.cpp выбран умолчанием (к тому же бесплатен и локален).

### Основная модель

Тот же каркас с усилением узкого места (шум ASR загрязняет и конспект, и измерение):

1. **Реконструкция транскрипта** — новая LLM-стадия: чистка филлеров/вопросов/оффтопа, исправление ошибок ASR, устная математика → LaTeX. 46k → 8,6k слов при *росте* числа атомарных утверждений (526 против 449) и без сокращения пула transcript-only (334 против 294) — сжатие является чисткой, а не скрытой суммаризацией.
2. **Перегенерация конспекта** из восстановленных транскрипта и слайдов (structured output, разметка источников через pydantic).
3. **Улучшения оценки:** метки значимости, ретривер `BAAI/bge-small-en-v1.5`, top-k = 16; кэширование стадий по отпечатку настроек.
4. **Слой квизов (E3):** генерация из конспекта, сбор попыток через веб-приложение, item analysis, отбраковка и регенерация.

Результаты (лекция 6, тот же судья и STT):

| метрика | бейзлайн | **основная** |
|---|---|---|
| coverage | 53,9 % | **62,5 %** (core: 68,6 %) |
| faithfulness | 69,4 % | **86,5 %** |
| F1 | 60,7 % | **72,6 %** |
| transcript-only сохранено | 37,2 % | **48,5 %** (core: 52,4 %) |

За числами — валидность судьи (κ = 0,95, 0 FP). Изменения (лучший конспект, честнее измерение, больший top-k) пока смешаны — запланирована абляция. Осталось: прогон замороженного пайплайна по 8 held-out лекциям, таблица задержек/стоимости E2, применение цикла отбраковки-регенерации E3.

#### E3: item analysis по production-попыткам

**33/45 вопросов (73 %) проходят правило отбраковки.** Сложность попадает в цель (средняя p = 0,61; 39/45 в окне [0,30; 0,85]); слабая ось — дискриминативность (средняя r_pb = +0,42, но у 7 вопросов она отрицательная). Три квиза полностью чистые; каждый сохраняет ≥ 2 пригодных вопроса. 12 отбракованных распадаются на три типа отказа:

- **слишком лёгкие (2):** p = 1,00, r_pb не определена — «факт, который помнят все»; первые кандидаты на регенерацию;
- **слишком трудные (4):** p = 0,20; у двух вопросов лекции 7 при этом r_pb = +0,71 и общий дистрактор у 3 из 5 — либо притягательное заблуждение, либо спорный ключ ответа: перед регенерацией нужна ручная проверка;
- **низкая дискриминативность (6):** r_pb от −0,69 до −0,08 — единственный промах принадлежит сильному респонденту, что на малой выборке резко уводит r_pb в минус.
