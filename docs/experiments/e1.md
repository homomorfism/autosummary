# E1 — claim-level summary evaluation

**Code:** `app/e1.py` · **Artifacts:** `<lecture-dir>/e1/` · **Run:** `uv run python -m app.e1 <lecture-dir>`

## Goal

Measure how good the generated conspect (`conspect.md`) is as a summary of its
two sources — the slides and the spoken lecture — at the level of **atomic
facts**, not surface text overlap (ROUGE/BLEU say nothing about whether a fact
survived). Three questions:

1. **Coverage (recall):** what share of the facts in the sources made it into
   the conspect?
2. **Faithfulness (precision):** what share of the facts in the conspect is
   actually supported by the sources (i.e. not hallucinated or distorted)?
3. **Transcript-only preservation** — the project's thesis ("site > deck") in
   one number: of the facts the lecturer *said* but the slides *don't show*,
   how many did the conspect keep? A slides-only summarizer would score ~0 here.

## Pipeline

```
slides_reconstructed.md ────────┐
transcription_reconstructed.md ─┼─► 1. decompose ─► claims.json ─► 2. retrieve + judge ─► judgments_*.json ─► 3. metrics ─► e1.json
conspect.md ────────────────────┘
```

### 1. Decomposition → `e1/claims.json`

Each of the three texts is chunked (~2 000 words on line boundaries; a chunk
whose claims overflow the completion budget is split in half and retried) and
an LLM extracts **atomic, self-contained factual claims** ("self-contained" = pronouns
and references resolved, so a claim can be judged with no surrounding context).

- **Slides** use `slides_extracted/slides_reconstructed.md` — the same
  LLM-cleaned source the conspect was built from. The raw `slides.md`
  duplicates beamer overlay frames and mangles math, which would corrupt the
  claim set.
- **Transcript** uses `<stt-provider>/transcription_reconstructed.md` — the
  LLM-cleaned transcript produced by `app.reconstruct_transcript` (raw ASR
  minus filler, Q&A, off-topic anecdotes, administrative talk, foreign-language
  speech; obvious recognition errors repaired; spoken math as LaTeX). This is
  the same source the conspect is built from, so both directions compare like
  with like. Falls back to the raw `transcription.md` with a warning.
  Timestamps are stripped before decomposition.
- **Summary** uses `conspect.md` as-is.

Every claim carries a **salience** label assigned during extraction:

| label | meaning |
|---|---|
| `core` | a main teaching point: definition, theorem, key formula, mechanism, central result — something a good summary *must* keep |
| `supporting` | elaboration of a core point: derivation step, worked example, concrete number, comparison, practical advice |
| `aside` | tangential to the taught material: historical anecdotes, speaker opinions, meta-commentary |

Salience exists because a conspect is *supposed* to drop asides: without it,
every omitted anecdote counts as a coverage failure and the unweighted coverage
number understates summary quality. The `*_core` metrics restrict coverage to
core claims.

### 2. Entailment: retrieve + judge → `e1/judgments_<direction>.json`

`entails(claim, premise_set)` is implemented as **top-k retrieval** over the
premise claims followed by a **batched LLM judge**:

- **Retrieval** — sentence-transformers embeddings (`E1_EMBED_MODEL`, default
  `BAAI/bge-small-en-v1.5`; cosine over normalized vectors; top-k defaults to
  16), with a dependency-free TF-IDF fallback when the package is not
  installed. Retrieval only needs good recall@k — the judge makes the actual
  decision.
- **Judge** — a strict NLI prompt: `entailed` only if the claim's *full*
  content follows from the retrieved premises (paraphrase, direct consequence,
  or a combination of premises); topical overlap or partial support is not
  enough. Judged in batches of 8 claims per LLM call.

Three directions:

| direction | targets ⊑ premises | produces |
|---|---|---|
| `coverage` | slides + transcript claims ⊑ summary claims | coverage (recall) |
| `faithfulness` | summary claims ⊑ slides + transcript claims | faithfulness (precision) |
| `transcript_vs_slides` | transcript claims ⊑ slide claims | the transcript-only mask |

### 3. Metrics → `e1/e1.json`

- `coverage`, `coverage_slides`, `coverage_transcript` — share of source claims
  entailed by the summary, overall and per source.
- `coverage_core`, `coverage_transcript_core` — the same restricted to `core`
  claims.
- `faithfulness` — share of summary claims entailed by the sources.
- `f1` — harmonic mean of coverage and faithfulness.
- `transcript_only_claims` / `transcript_only_coverage` — spoken claims **not**
  entailed by the slide claims, and the share of them the summary kept.
- `transcript_only_core_claims` / `transcript_only_core_coverage` — the thesis
  metric restricted to core claims.

## Commands

```bash
# full run (hundreds of LLM calls; ~20 min at --workers 12 on one lecture)
uv run python -m app.e1 data/<course>/<lecture> --workers 12

# cheap smoke run: 1 chunk per source, 10 claims per source
uv run python -m app.e1 data/<course>/<lecture> --max-chunks 1 --limit 10

# knobs
uv run python -m app.e1 <dir> --stt google_stt          # judge against the other transcript
uv run python -m app.e1 <dir> --model claude-opus-4-8   # different decompose/judge LLM
uv run python -m app.e1 <dir> --retriever tfidf         # skip embeddings
uv run python -m app.e1 <dir> --top-k 8                 # fewer premises per judged claim
uv run python -m app.e1 <dir> --force                   # ignore all caches
```

The transcript side expects `transcription_reconstructed.md`; produce it (and
then the conspect) before evaluating:

```bash
uv run python -m app.reconstruct_transcript data/<course>/<lecture>   # raw ASR → cleaned transcript
uv run python -m app.conspect data/<course>/<lecture>                 # uses the reconstruction when present
```

### Judge calibration (manual labels)

The judge is itself an LLM, so its error rate must be estimated before the
metrics are trusted:

```bash
uv run python -m app.e1 <dir> --sample-labels 40   # writes e1/labels_manual.json
# … fill in "manual_entailed": true/false for each sampled pair …
uv run python -m app.e1 <dir> --agreement          # judge-vs-human agreement + FP/FN split
```

## Caching

Every stage writes to `<lecture-dir>/e1/` with a settings **fingerprint**
(prompt version, STT provider, LLM, embedding model, chunking, top-k, debug
limits). A stage whose fingerprint matches is skipped on rerun; a mismatch — or
`--force` — recomputes it. Interrupted runs resume from the last finished
stage.

## Cost model

Let `C` = total chunks across the three sources, `N_cov`, `N_faith`, `N_tvs` =
target-claim counts of the three directions, `B` = judge batch size (8):

```
LLM calls ≈ C  +  ⌈N_cov/B⌉ + ⌈N_faith/B⌉ + ⌈N_tvs/B⌉
```

For lecture-06 that was 10 decompose + ~177 judge calls. **`--top-k` does not
change the number of calls** — it adds `k` premises to each judged item, so
judge *input* tokens grow roughly linearly with `k` (output stays the same:
one verdict per item). Embedding retrieval is local and free.

## Results — lecture-06 (deep-learning-and-computer-vision)

Three runs, 2026-07-06, all with `deepseek-v4-pro` for decompose/judge and the
whisper_cpp transcript. The pipeline changed between runs:

1. **Baseline** — raw ASR transcript, no salience labels, `all-MiniLM-L6-v2`
   retriever, `top_k=8`. The conspect was built from the raw transcript.
2. **Cleaner decomposition** — same conspect, but claim extraction got salience
   labels + off-topic filtering rules, retriever swapped to
   `BAAI/bge-small-en-v1.5`.
3. **Reconstructed transcript** — new `app.reconstruct_transcript` stage
   (46k → 8.6k words), conspect **regenerated** from the cleaned transcript,
   off-topic rules moved out of decomposition into the reconstruction,
   `top_k=16`.

| metric | 1 baseline | 2 clean decompose | 3 reconstructed |
|---|---|---|---|
| coverage | 53.9% | 51.5% | **62.5%** |
| coverage (core only) | — | 64.9% | **68.6%** |
| coverage: slides / transcript | 70.9% / 48.8% | 63.3% / 49.0% | 70.1% / **60.3%** |
| faithfulness | 69.4% | 73.6% | **86.5%** |
| F1 | 60.7% | 60.6% | **72.6%** |
| transcript-only preserved | 37.2% (of 349) | 37.4% (of 294) | **48.5%** (of 334) |
| transcript-only preserved (core) | — | 49.2% (of 120) | **52.4%** (of 168) |
| claims: slides / transcript / summary | 151 / 494 / 278 | 98 / 449 / 254 | 157 / 526 / 208 |

Reading the jump from run 2 to run 3 — three confounded effects (no ablation
was run to separate them):

- the conspect itself improved (built from a clean, dense transcript);
- the measurement got fairer (conspect and transcript claims now come from the
  same cleaned source, so ASR noise no longer counts against either direction);
- `top_k` 8 → 16 lets compound claims gather all their supporting premises
  (mostly benefits faithfulness).

Evidence that the 5.4× transcript compression was cleaning rather than hidden
summarization: decomposition extracted *more* atomic claims from the 8.6k-word
reconstruction than from the 46k-word raw transcript (526 vs 449), and the
transcript-only pool did not shrink (334 vs 294). A manual spot-check of raw
chunks against their reconstruction has not been done yet.

### Judge calibration — lecture-06, 2026-07-12

40 judged pairs sampled with `--sample-labels 40`, labelled by hand, scored
with `--agreement`:

```
uv run python -m app.e1 data/deep-learning-and-computer-vision/lecture-06 --agreement
# judge vs manual: 39/40 agree (98%); judge said entailed but human said no: 0; missed by judge: 1
```

| | human: entailed | human: not entailed |
|---|---|---|
| **judge: entailed** | 21 | 0 |
| **judge: not entailed** | 1 | 18 |

Observed agreement **97.5%**, Cohen's κ = **0.95**. Zero false positives means
the judge never granted entailment the human rejected, so faithfulness is not
inflated; the single miss (a transcript_vs_slides pair) means coverage-style
numbers are, if anything, slightly conservative. Sample was 21 coverage /
5 faithfulness / 14 transcript_vs_slides pairs. With n=40, the 95% CI on
agreement is roughly 87–100% — report as "κ≈0.95 on a 40-pair sample", not as
an exact reliability figure.

## Known limitations / next steps

- **Judge strictness:** sampled false negatives show the judge sometimes
  rejects clear paraphrases or compound claims where one minor sub-fact wasn't
  retrieved. The lecture-06 calibration (above) bounds this at 1 miss / 40
  pairs, but recalibrate after any judge-prompt or model change.
- **Both sources are LLM reconstructions:** slides and transcript claims come
  from LLM-cleaned texts, not the raw PDF/ASR. Anything the reconstruction
  drops or distorts is invisible to the metrics — coverage and faithfulness
  are measured against the reconstruction, not the primary source.
- **Salience is judged by the same LLM** that decomposes; its core/aside split
  has not been human-validated yet.
- No cross-source claim dedup (measured near-duplicate rate within the
  transcript is ~0, so this is currently a non-issue).
