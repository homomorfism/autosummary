**[00:46]** Today we discuss generative adversarial networks (GANs), a beautiful idea that is entirely non-mathematical at first but logically compelling and leads to elegant mathematics later. Before that, I want to give the overall structure of generative AI: what kinds of deep generative models exist.

**[01:35]** “Generative AI” is not a precisely defined term; even logistic regression generates a probability distribution over classes. The key divide is that generative models produce something big—an object of high dimension and complicated structure, such as an image or text. These models write, draw, produce music or videos. We focus on deep generative models based on neural networks. There are several important classes; today we explore one, and tomorrow another. I will sketch a general taxonomy to clarify.

**[03:01]** The first major fork in deep generative models is between explicit density models and implicit density models. When a generative model takes input (e.g., random noise) and outputs an object (a cat photo), the output $x$ lives in a very high-dimensional space with an extremely complicated distribution $p(x)$. In an explicit density model, the model provides an explicit formula for $p(x)$—or at least an approximation—so you can, in principle, evaluate it. In an implicit density model, there is no such formula; the model simply samples from the distribution.

**[05:12]** Inside explicit density models, the next divide is tractable density models. Tractable means you can actually write down a formula for $p(x)$. The classic approach is autoregressive modeling, which uses the chain rule: $p(x) = p(x_1) p(x_2 \mid x_1) p(x_3 \mid x_1, x_2) \dots p(x_n \mid x_1, \dots, x_{n-1})$. This identity is always true but useless in practice because the conditionals are still huge. You simplify by making assumptions—for example, a Markov assumption that each $x_k$ depends only on the previous few, or using an RNN where each output depends on the current input and a hidden state. Most LLMs are in this class: they model text by predicting the next token, $p(x_k \mid \text{context})$, with transformers modeling the conditionals. For images, PixelCNN once generated pixels one by one; it produced good outputs but was far too slow because generating a million pixels requires a million model runs. Therefore pixel-wise autoregressive models are rarely used today, though they exist. For text, essentially everything is autoregressive.

**[09:17]** Still within tractable density, you can also have flow-based models. Instead of decomposing $p(x)$ along the variables, you model it as a composition of simple transformations: $x = f_k \circ f_{k-1} \circ \dots \circ f_1(z)$, where each $f_i$ is something like adding Gaussian noise or a linear transformation. Just as with deep neural networks, composing many simple transformations can model very complex distributions. Regrettably, we won’t have time to cover flow-based models in detail.

**[10:46]** Apart from tractable density, explicit density models also include approximate density models. Here, rather than making assumptions about $p(x)$ itself, we explicitly approximate $p(x)$ by a simpler distribution $q$—for example, a product of easier factors. The most important example, and one we may discuss tomorrow, is the variational autoencoder (VAE). VAEs use variational approximations to derive good loss functions for generative models and are used extensively. For example, diffusion models (the topic of the next lecture) typically operate in the latent space of a VAE.

**[12:09]** The implicit density side is much less rich. There are very few mainstream examples; the primary one is GANs, which we discuss today. In an implicit density model, you have no formula for $p(x)$ at all. How can you produce cat photos without a density? The model simply takes random noise (e.g., a standard Gaussian) and transforms it into a sample that should be drawn from the target distribution. It is a sampler, not an explicit distribution. The neural network is a black box that maps a simple distribution to the complicated one; you cannot extract a density formula from it. That is precisely what GANs do.

**[14:41]** What are GANs? What is their main idea? Generative adversarial networks (GANs) are one possible solution to a very deep problem in generative models. The main problem you need to solve when creating a generative model is: what is your loss function? How do you score the results?

**[16:08]** I start with a random noise $Z$ taken from some standard distribution. This $Z$ is fed into the generator network, which maps it to an output $\hat{X}$ that is supposed to be a cat picture. Think of it as a machine learning problem: we have a dataset of many cat photos, the real $X$'s. But we have no paired data—we cannot say that $\hat{X}$ should be similar to a specific $X$ in the training set because there is no such correspondence. There is no dataset pairing random noise with images that should be produced from it. The whole point of learning a generator is to learn this mapping and to obtain a good, relatively simple parameterization in noise space so that we can later sample random noise and get reasonable cat pictures. So the data is unlabeled; it is unsupervised learning. Where will the loss function come from? Which $X$ should $\hat{X}$ be similar to? We can say: I don't have a specific $X$ in mind; I just want $\hat{X}$ to be a good cat picture. That sounds reasonable, but what does it mean to be a good cat picture? There is really no mathematical function you can run to say whether a set of pixels is a good cat picture. This is something you have to learn yourself—half, if not most, of the problem.

**[19:09]** Generative adversarial networks recognize that you need to learn your loss function. You do not have a fixed formula for evaluating how cat-like an image looks. So let's work for it. Let's have a whole separate network, a discriminator, whose only job is to say whether the input is fake or real. As input it takes photos, and as output it does binary classification: real (1) or fake (0). The discriminator gets a picture: if it was produced by the generator, it should output 0 (fake); if it is a real picture sampled from the dataset, it should output 1 (real). So we have real $X$ and fake $\hat{X}$. In this way, the generator and the discriminator are at odds with each other: the discriminator wants to learn to distinguish real images from generated images, and the generator wants to fool the discriminator. This idea is called adversarial training.

**[21:15]** GANs are not what they used to be; for the last few years GANs have not been at the forefront of image generation—images these days are generated by diffusion models. But adversarial training is very much alive. Even in diffusion models, we will see exactly this idea, a GAN embedded into a diffusion model making it better. This is still a very important idea in machine learning and appears in many different fields.

**[22:17]** Let me show you some introductory pictures. The main idea is very simple: the generator is like a forger producing counterfeit pictures, and the discriminator is the detective that needs to decide whether it is real.

**[22:43]** For example, the generator (here a reverse deep convolutional neural network) learns to produce pictures of money. At first it just produces random noise, then some very bad counterfeits. The discriminator, initially untrained, might be fooled. Then we train the discriminator, and it learns to distinguish that this is not real money. Then we train the generator to fool this current version of the discriminator, so the generator improves and produces a slightly better counterfeit. The process continues: the discriminator finds new features to discriminate on, and the generator must learn to fake those features. So they play this game, and the hope is that eventually everything happens as in an idealized image.

**[24:53]** In the idealized picture, the generator is represented by arrows. In $Z$ space we have a uniform distribution, and in $X$ space we have a Gaussian (green); the black dots are the data points. At first the Gaussian does not match the data. The blue dashed line is the discriminator, a logistic sigmoid that distinguishes between the two. The generator learns to fool the discriminator—it moves the Gaussian a little bit so that the discriminator is fooled even without going all the way to the data points. But then the discriminator adapts, and the cycle repeats. Finally, we hope to reach the perfect picture where the generator is perfect and the discriminator has no idea what to do and just flips a coin. In real life it does not work exactly like that, but the idea is this.

**[26:34]** What is interesting about the problem setting? Let's write down the loss functions mathematically. First, the discriminator loss $L_D$. The discriminator is supposed to output zero for fake and one for real. If I take a real photo from the training set, I am supposed to increase the output—push the score to positive infinity so that after the sigmoid the probability goes to one. So the loss should contain something like $\log D(x)$.

**[27:49]** For a real sample $x$, the discriminator’s loss is $-\log D(x)$. For a fake sample $x$ drawn from the generator distribution $p_g(x)$, the discriminator should output zero, so the loss is $-\log(1-D(x))$. Minimizing this loss with respect to the discriminator’s parameters while the generator is fixed is a straightforward binary classification problem.

**[28:51]** The generator, on the other hand, is supposed to produce samples that pass as real to the discriminator. It cannot affect the loss on real data, but for the fake data term it does the opposite: where the discriminator minimizes $-\log(1-D(G(z)))$, the generator minimizes $+\log(1-D(G(z)))$ (or equivalently $-\log D(G(z))$). The two can share a single loss function, $V(D,G)=\mathbb{E}_{x\sim p_{\text{data}}}[\log D(x)]+\mathbb{E}_{z\sim p_z}[\log(1-D(G(z)))]$, with the discriminator trying to maximize it and the generator trying to minimize it—a minimax game.

**[30:45]** This adversarial setup is not ordinary optimization; it is a minimax problem from game theory, which is notoriously hard. But there are properties that simplify it. If the generator is fixed, the optimal discriminator is exactly the Bayes classifier: the probability that $x$ is real is $p_{\text{data}}(x)/(p_{\text{data}}(x)+p_g(x))$. Plugging this optimal discriminator into the generator’s objective shows that the generator attains its global minimum if and only if $p_g=p_{\text{data}}$, confirming that it is driven toward the true data distribution. Moreover, under the optimal discriminator, the generator minimizes the Jensen–Shannon divergence between $p_g$ and $p_{\text{data}}$, not the more common Kullback–Leibler divergence. These theoretical results, however, are ultimately irrelevant in practice.

**[34:42]** All that theory assumes a shared loss function, but in practice using the flipped binary cross‑entropy as the generator loss is a bad idea because it saturates. The discriminator’s output goes through a sigmoid; when it is very confident and correct, its gradients become extremely small. For the discriminator, this is harmless, but for the generator it is catastrophic: if the discriminator easily separates real from fake, the generator is failing, yet the backpropagation signal to the generator must travel through the discriminator. Once the discriminator has saturated after a few alternating training steps, the generator’s gradients vanish and it can no longer learn. The solution is to change the generator’s loss.

**[38:27]** The original GANs appeared in 2014. Early results—showing green real training images and their nearest neighbors—confirm that the models generated new samples, not mere memorizations. They worked wonderfully on MNIST, much worse on small black‑and‑white faces, and were poor on anything more diverse. Back then, GANs were not yet competitive with other generative models. Then came DCGAN, which introduced a convolutional architecture for both generator and discriminator. DCGAN started producing reasonable images on some datasets, still small and flawed—but that was state of the art a decade ago. As a side remark, if you look through old generative modeling papers on GANs, VAEs, and the like, you will see a great many bedrooms.

**[40:42]** A dataset called Large Scale Scene Understanding (SU) contains subsets of photos of different environments, including bedrooms. After someone chose bedroom images for their tests, it became a standard benchmark, so you will see many bedroom pictures. They are relatively small—64×64 or 128×128 pixels—but in color and meant to resemble real photos.

**[41:33]** The DCGAN after one epoch is still very bad, but after five epochs it becomes more or less okay. Nothing exciting by today’s standards, but it was acceptable back then.

**[41:56]** It is important to understand whether you have a good generative model. The discriminator cannot tell you that: it may fail to distinguish, but that does not mean the images or the latent space are good—the discriminator might simply be undertrained or too small. To see if the generator makes sense, a visual illustration is used.

**[42:46]** The generator takes a random noise vector $Z$ from the latent space and maps it to a point $X$ in pixel space. Realistic images form an extremely complicated manifold in pixel space, and the latent space is meant to flatten that structure. Our goal is to sample $Z$ from a simple distribution (e.g., a standard Gaussian) and have $G(Z)$ land on that manifold.

**[45:14]** A popular test is a linear walk in the latent space. Take two different latent vectors $Z_1$ and $Z_2$; they produce two different images. Walking along the straight line from $Z_1$ to $Z_2$ in the latent space, all intermediate $Z$ should yield reasonable images. If the generator $G$ simply memorized a few training points and mapped $Z$s to those, it might still look good on the training set, but interpolated images would be nonsensical. For instance, walking along a straight line in pixel space would blend the two images by transparency rather than produce realistic intermediate photographs. Ideally, the path in pixel space follows the manifold, so every step remains a realistic image. Consistently observing that suggests the generator can produce realistic images from random $Z$.

**[48:22]** In generative model papers, you often see such latent space walks: the leftmost and rightmost images are real or guaranteed good, and the intermediate frames are generated from interpolated $Z$. They may show some strange artifacts but mostly remain realistic. This was state-of-the-art image generation about ten years ago.

**[49:26]** That was state of the art a decade ago—marvel at the rate of progress. These were not photorealistic bedroom photos; common failure modes included counting problems. The recent meme about six fingers on a hand was still an issue a couple of years ago, but ten years ago it was much worse: three-headed dogs with many eyes. Such failures make sense given the reverse convolutional architecture: it captures general features and then specializes local parts more or less independently, with limited context. When generating an eye, the network may not know whether it is a left or right eye, so it might draw another eye, and another, misaligning perspective when continuing a dog’s body. These mistakes stand out to us because human vision is highly trained, but learning proper 3D perspective and object coherence is very difficult.

**[52:52]** Among example images, it often takes a few questions for people to notice that one cat is actually a real photograph—just a cat sleeping curled up. It is hard. Image generation has made tremendous progress; by 2018 you probably cannot see imperfections, so showing newer models would be pointless.

**[54:03]** There are imperfections in generated faces, but on a slide they are not visible. Comparing images from 2014 and 2017 shows tremendous progress in GAN-based generation in only a few years. How did that happen? I will concentrate on the key technical ideas, and I want to discuss one conceptually interesting idea that illuminates how latent spaces work.

**[54:56]** An important technical idea is that you do not need to generate a whole picture at once. This can be cast as a conditional generation problem: you give a condition and the output changes accordingly. A relatively simple version is super-resolution. Super-resolution is a generative problem because you are inventing new detail when scaling a low-resolution image to high resolution, but it is easier than generating images from scratch since the overall structure is already given.

**[56:16]** The idea for general generation was therefore to start small and then apply a sequence of super-resolution steps. This was called ProGAN, Progressive Growing GAN, which produced the famous realistic faces shown on the website *ThisPersonDoesNotExist*. The process trains a simple GAN to generate 4×4 human faces; even from scratch this is not hard. Then these 4×4 outputs are used as conditions for super-resolution to 8×8, then 16×16, 32×32, and so on. After about two weeks of training on NVIDIA hardware—which gave them a large compute advantage at the time—the result was a 1-megapixel image of very high quality.

**[58:28]** The more interesting part is the loss function. By that time, two main loss functions for GANs existed. One was the least squares GAN, which addresses the saturation problem in a straightforward way. Instead of using a sigmoid, it uses a squared deviation from a target constant (e.g., 1). Overshooting the target is also penalized, so nothing blows up and everything clusters around the constant. Least squares is usually a bad idea for classification, but here it works precisely because it avoids saturating gradients.

**[1:00:19]** The conceptually deeper idea is the Wasserstein GAN (WGAN). To see its motivation, ask: what does it mean for two distributions to be close? Usually in machine learning we minimize the Kullback–Leibler (KL) divergence. The KL divergence from $p$ to $q$ is defined as
\[
D_{\mathrm{KL}}(p\|q) = \int p(x) \log \frac{p(x)}{q(x)} \, dx .
\]
When $p$ and $q$ are identical, the ratio is one, the log is zero, and the divergence vanishes. Typically we minimize something like this, though note that $D_{\mathrm{KL}}(p\|q)$ and $D_{\mathrm{KL}}(q\|p)$ are not symmetric and have different properties.

**[1:02:44]** Usually we apply KL divergence in relatively low-dimensional spaces. In generative image models, however, $x$ is a very high-dimensional vector of pixel values. The true data distribution $p_{\mathrm{data}}(x)$ and the generator distribution $p_g(x)$ are both concentrated in low-dimensional manifolds of that high-dimensional space. If we imagine a 2D plane as the image space, $p_{\mathrm{data}}$ might be concentrated along one straight line, and $p_g$ along another. Because each distribution lives on a thin subset, their supports are disjoint with probability one: where $p_{\mathrm{data}}(x)$ is non-zero, $p_g(x)$ is zero, and vice versa. In this situation the KL divergence becomes infinite and meaningless. Tweaking the generator a little bit—moving its line—does not change the infinite value, so the KL divergence provides no useful gradient for training. Wasserstein distance was designed to solve exactly this problem.

**[01:07:23]** It will still not match the green line, and the Kullback–Leibler divergence will remain infinite. I will not be able to distinguish the correct direction from the wrong one; this kind of loss says nothing about which way to move.

**[01:07:56]** This seems to invalidate much of machine learning, because we are always trying to match distributions that often lie in separate subspaces. So why does the same problem not occur in, say, linear regression?

**[01:08:25]** In linear regression we have data points, the correct straight line, and our current incorrect line. They also do not overlap—they intersect at a single point of measure zero. Yet the effect does not happen because we add noise. The assumed straight line has non‑zero likelihood thanks to the added noise. pData is fixed, but we smooth out pG by adding, for example, Gaussian noise, so pG(x) > 0 everywhere. It can be exponentially small, but that is enough.

**[01:22:44]** We cannot match two distributions with disjoint or almost disjoint supports. In classical machine learning we add noise, so that pG becomes a low‑dimensional model plus Gaussian noise extending over the whole space; then the KL divergence works and we can maximise likelihood. In linear regression we assume Gaussian noise around the line, learn the line, but when we predict a new point we do not add artificial noise—we simply use the expectation. For implicit density generative models, however, we cannot drop the noise after training because the output already includes it. Adding noise makes images blurry and unrealistic, so we do not want noise in such models. The Wasserstein GAN therefore introduces a loss function that works without adding noise, based on the Earth Mover distance.

**[01:27:33]** The Earth Mover (or Wasserstein) distance is easy to understand. Think of each distribution as a pile of earth with total volume 1. You can shovel one pile to the other. As you move earth, you do physical work—mass times distance. If you take the optimal transport plan, the minimal amount of work needed to transform one distribution into the other, that is the Earth Mover distance. The idea is to match the two distributions while spending as little effort as possible.

**[1:29:43]** The Earth-Mover distance measures the minimal effort needed to transport one distribution to another, and we want to minimize this quantity. This may sound infeasible because it is a minimization inside a minimization, but mathematical techniques allow us to circumvent it. Once implemented, the loss function works even when the real and generated distributions have disjoint support—moving the generated distribution closer reduces the distance, so no artificial noise is needed. Wasserstein GAN remains one of the most popular loss functions for GANs and adversarial training.

**[1:31:23]** BigGAN, introduced in 2019, already produced reasonable images with nice interpolations. For example, one can transition from a bird to a dog, and the intermediate artificial hybrids still kind of make sense.

**[1:32:04]** We have discussed generative models, GANs, and the Wasserstein GAN loss. The final idea, which leads into variational autoencoders and deepens our understanding of generative models, is the adversarial autoencoder. The main challenge in generative modeling is defining a loss function: how do you measure whether a generated image is a good cat picture? One natural answer is to train an autoencoder. We take an image $X$ from pixel space, encode it to a latent code $Z$ in a smaller, more understandable space, and then decode $Z$ back to a reconstruction $\hat{X}$. The autoencoder provides a straightforward $L_2$ loss between $X$ and $\hat{X}$, encouraging $Z$ to be a good compressed representation. At first glance, the decoder looks like a generative model. However, we cannot simply discard the encoder and use the decoder as a generative model. The $X$'s live in a million-dimensional space, and even the relatively low-dimensional latent space (say 500 dimensions) contains a complicated manifold of $Z$'s from real images. If we sample $Z$ from a standard Gaussian, we will almost never land on that manifold, and the decoded image will be nonsensical, not a nice cat picture.

**[1:37:45]** To fix this and use autoencoders as generative models, we must regularize the latent space. One approach is the variational autoencoder, which we will discuss tomorrow. Alternatively, we can take an adversarial approach: treat the $Z$'s coming from real images as fake, and let the “real” $Z$'s be drawn from a simple prior such as a standard Gaussian. Then place a discriminator not on images but on latent codes, to distinguish between the encoded latent codes and samples from the prior. The encoder is trained to fool the discriminator. If the discriminator cannot tell them apart, then sampling $Z$ from the standard Gaussian should yield latent codes that the decoder interprets as realistic images. This adversarial autoencoder is an old idea, nearly as old as GANs themselves. Variational autoencoders offer a cleaner conceptual solution and are more widely used, but adversarial autoencoders can sometimes perform better depending on the implementation and are covered in the practical sessions. Modifications are straightforward; for instance, to generate a specific MNIST digit you can condition the distributions on labels, so each label gets its own latent distribution.

However, for straightforward image generation or text-to-image tasks, they have been completely replaced by diffusion models.
