**[00:01]** Today we discuss transformers, the most important lecture in the course. But first, we need to finish recurrent neural networks from yesterday, then attention mechanisms, and from recurrent attention we arrive at self-attention and transformers, which transformed deep learning a decade ago.

**[00:49]** Yesterday we stopped at the main problems of recurrent networks; I omitted a point. These problems are the same as in deep networks generally, such as convolutional nets—the signal saturates. In deep networks, as you go through the layers (especially gradients), when a layer saturates its derivatives become zero, and multiplying by zero prevents everything below from training. A recurrent network is essentially a very deep network: although we think of one input at a time, activations actually pass through as many trainable weight layers as there are sequence elements. Even a single-layer RNN is as deep as the input length. So-called deep RNNs stack multiple recurrent layers, but any RNN is inherently deep. The problem is identical. As gradients flow backward (or activations forward), strange things happen because you repeatedly multiply by the same weight matrix. In RNNs this is exacerbated by parameter sharing: the same $W$ is used at every step. Vanishing gradients occur when the spectral radius of $W$ is less than $1$; then gradients are multiplied by a number $<1$ repeatedly and shrink to zero.

**[05:03]** This is problematic, but vanishing gradients are especially insidious. Unlike exploding gradients—where you see numerical overflows and everything breaks down—vanishing gradients do not stop training of $W$. $W$ still participates in the last timesteps, so gradients w.r.t. $W$ are not zero, and the loss may appear to improve. However, the network effectively bases its decisions only on the last few elements of the sequence and cannot capture long-term dependencies: $x_1$ cannot influence the output at step $t$. The network lacks long-term memory.

**[07:24]** The solution mirrors the residual connections we saw in ResNets: add a path for gradients to bypass weight multiplications. This idea actually originated with recurrent networks, because RNNs don’t work without it. It was introduced in the 1990s by Jürgen Schmidhuber’s group; these “highway” constructions were only applied to deep feedforward nets around 2015, since we lacked very deep networks before. The principle is to create a highway for gradients to flow, modifying the highway’s content without direct multiplication by a potentially vanishing weight matrix. The classic implementation is the Long Short-Term Memory (LSTM), which builds such a highway for memory flow.

**[09:18]** In an LSTM cell, the inputs are the previous hidden state and the current input $x_t$, and the outputs are the next hidden state components. The hidden state is conceptually split into two parts treated differently: the long-term memory $C_{t-1}$, which serves as the highway—it undergoes read/write operations but is not directly multiplied by weight matrices, analogous to a residual path—and a regular hidden state $h_{t-1}$ that participates in gating. The cell is built from gates. A generic gate takes two inputs (e.g., $h_{t-1}$ and $x_t$), multiplies each by a weight matrix, adds them (plus a bias), and applies an activation function, outputting $f(A x + B y)$. These gates are combined in creative ways.

**[12:58]** The first gate is the forget gate. It takes $h_{t-1}$ (multiplied by $W_{hf}$) and $x_t$ (multiplied by $W_{xf}$), sums them, applies an activation, and then the output is multiplied element-wise with the previous cell state $C_{t-1}$, allowing the network to forget parts of the memory.

**[14:16]** The forget gate's output is a vector $f_t$, which multiplies the cell state $c_t$ component-wise. The forget gate is a linear combination of $h$ and $x$, passed through a logistic sigmoid, which squashes values into $(0,1)$. Multiplying $c_t$ by values near $0$ erases information; multiplying by values near $1$ retains it. This gating mechanism is a common neural network pattern: a small sub-network produces a control vector that governs operations elsewhere in the model.

**[15:57]** Gates are not data; they are control signals. True logic gates cannot be used because they are piecewise constant and prevent gradient flow. Instead, sigmoids provide a continuous, differentiable approximation that saturates near 0 and 1, enabling training.

**[17:19]** Next, the candidate cell state $\tilde{c}_t$ generates new values to write into memory. It is also computed from $h$ and $x$ via weight matrices, but typically uses a $\tanh$ activation rather than a sigmoid. Unlike the forget gate, the $\tanh$ here is not essential and could be modified; in classical LSTMs it is simply one choice.

**[19:03]** An input gate, again with a sigmoid, controls which parts of $\tilde{c}_t$ are written to memory. The gated candidate $\tilde{c}_t \odot i_t$ is added to the cell state. The addition is not performing arithmetic; it is the mechanism for writing after erasure: first the forget gate zeros out positions to be overwritten, then the input gate fills them with new values.

**[21:07]** The hidden state $h_t$ for the next time step is produced from the updated cell state $c_t$. A $\tanh$ is applied to $c_t$, and an output gate, again a sigmoid, determines which parts are read out. This gives $h_t = o_t \odot \tanh(c_t)$. The control vector $o_t$ is generated from $h$ and $x$ with matrices $W_{ho}$ and $W_{xo}$.

**[22:34]** The LSTM cell can be understood as a memory-manipulation program: you can erase from memory (forget gate), write new candidate information (input gate + candidate), and read from memory (output gate). This design makes clear intuitive sense, and only the choice of $\tanh$ at the output lacks a deep justification.

**[23:43]** LSTMs were first proposed around 1995 and essentially reached their modern form by the year 2000 in Schmidhuber's group. They remain highly successful and are still the default recurrent construction for many applications.

**[24:36]** The key architectural benefit is the cell state highway, where gradients flow backward without multiplication by recurrent weight matrices, except where intentionally interrupted by gate operations (e.g., when the forget gate zeros out a cell, gradients stop for that element, which is desired).

**[25:09]** The cost of LSTMs is the large parameter count. The cell-state update involves eight weight matrices (for combined $h$ and $x$ inputs to the three gates and the candidate). If $h$ and $c$ have dimension $d$ and $x$ has dimension $d'$, roughly half the matrices are $d \times d$ and half are $d \times d'$. Typical $d$ values range from 64 to 1000, and $d'$ is of similar order after embedding. Training large LSTMs remained difficult until around 2015 due to these heavy parameterizations.

**[27:04]** Big LSTMs are indeed what people use for big recurrent networks. For example, AlphaStar, the StarCraft playing network, was a recurrent network that used LSTMs. This first successful architecture for memory manipulation is now 25 years old and still stands; nobody has done better. Yet there have been many attempts to improve.

**[28:28]** The modern LSTM cell appeared in 2000. One modification added peephole connections: the gates originally had no access to memory, so you could not see what you were erasing. Adding inputs from the cell state adds more weight matrices. Later, people tried to reduce matrices, asking whether some gates could be removed. A famous paper, “LSTM: A Search Space Odyssey,” showed that on tested examples, you could actually remove a whole gate without much change.

**[30:13]** The goal is to have memory with a free gradient highway, but to make the cell more efficient. The Gated Recurrent Unit (GRU), developed in 2014, is similar to the LSTM but with fewer matrices. It does not distinguish between the cell state $C$ and hidden state $H$; there is just one hidden state. Instead of erasing and writing separately, the update gate performs a convex combination: it multiplies the current memory $H$ by $U$ and adds the candidate $\tilde{H}$ times $1-U$, where $U$ is a sigmoid-gated coefficient. The reset gate controls which part of the memory goes into the candidate. This eliminates the output gate and saves weight matrices; the GRU has six weight matrices compared to eight (or eleven with peepholes), so it should be more efficient.

**[33:22]** In 2015-2016, many NLP papers used GRUs and it seemed like a big shift. Then, for reasons not theoretically clear, the field switched back to LSTMs. AlphaStar, much later, used an LSTM. Empirically, LSTMs work better, though why is unknown. It is remarkable that the LSTM architecture has persisted so long.

**[35:15]** Like other architectures, recurrent cells have been subject to neural architecture search. A Google paper developed cells with only four weight matrices, similar to GRU but even more efficient. They outperformed LSTMs and GRUs on the tested datasets. However, these cells never gained widespread adoption; likely they do not generalize to other situations. The LSTM remains the best and still stands.

**[36:21]** With this, I want to end our discussion of recurrent networks. An illustration shows that repeated multiplication by a number less than one causes vanishing gradients, and greater than one causes exploding. A real experiment is the classic LSTM benchmark from Hochreiter and Schmidhuber. The input has two channels: one with random numbers in $[0,1]$, and another with markers — zeros except two ones. The task is to sum the two highlighted numbers. This is a toy memory test: you must memorize a value when the marker channel indicates, then retrieve and add the second value. LSTMs and GRUs both work on this; a simple linear RNN does not. In this simple problem, GRUs train much faster than LSTMs, which is the kind of plot that once convinced people GRUs are better. However, on very easy problems a more efficient cell may shine, but it likely does not scale to harder problems. Another sample shows the actual contents of memory for the LSTM.

**[40:34]** When the LSTM sees a marker, the value written to the cell spikes. The cell state grows to the correct sum, and the running guess tracks the true sum. Straightforward recurrent networks with a linear cell cannot maintain this long-term memory across many steps, and therefore cannot recall and add a number from 15 steps ago. This is the key idea behind all such recurrent cells.

**[41:54]** We now turn to the topic of attention. We approach it once more from a neurobiological motivation, but only superficially—staying at the level of how we think, not how neurons operate. Our brain seems to work very differently from the artificial neural networks we have seen so far. In computer vision, consider an image: our visual cortex is akin to a convolutional network in spirit, extracting local features and combining them into semantically richer global features. However, if I look at an image, my field of vision is wider than what I am attending to. I can miss events outside my focus even though they are in my visual field. A convolutional network, by contrast, extracts features from every part of the image and never loses objects; it cannot miss a cat, because a cat neuron will still activate. The difference is that we have an attention mechanism.

**[45:43]** Alexander Luria, a pioneer of neurobiology, identified attention as one of its three main pillars alongside memory and cognitive functions. Since Luria, we have learned that in the brain attention works through memory. Specifically, there is a working memory—a very short-term buffer that stores the last few items. Everything enters it, but then a filter selects which parts are important for further processing; that is where information gets lost. Even if you are not paying attention, you can recite the last five words I said, but you would not recall what I said 30 seconds ago.

**[48:58]** A classic demonstration is the invisible gorilla video, where viewers focused on counting basketball passes often fail to see a person in a gorilla suit walk across the screen. This shows that you can look directly at something without processing it. Our vision also uses a foveal spotlight: only a small central region is seen in high definition, while the periphery is blurry. We do not notice because our gaze constantly shifts (saccadic motion), and the brain integrates these snippets into a coherent scene. The original motivation for adding attention mechanisms to deep learning was to emulate this behavior—making parts of the input blurry to save weights and input size, thereby improving efficiency.

**[52:36]** Instead of processing a big image, you can use three snippets where only a few small parts are at full resolution and the rest is blurrier. Being blurrier means there are fewer pixels, so the input size becomes much smaller. Originally, attention mechanisms were used to save processing.

**[53:19]** In addition to recognizing or classifying from these blurred images, you need to choose where to look—the positions of the glimpses. These positions form a sequence, as the next glimpse can depend on what you see in the previous one. The first position can be chosen generally, but the second depends on the first. Early attention models were recurrent, leading to the field of recurrent visual attention, but that is now outdated. The point was to walk around a big picture, choose where to look, and blur the rest, achieving more accuracy while being more efficient with a recurrent mechanism for choosing glimpses.

**[55:07]** More relevant is attention applied to encoder-decoder mechanisms. Let me explain the problem using machine translation as motivation. For encoder-decoder architectures, you have an input like "hello world!" that is read into a hidden state, and the last hidden state produces a vector Z, an intermediate representation of the input sentence. Then Z is decoded into the output, such as "Privyet, mir!" In practice, the decoder might have a hidden state and Z is input to every cell.

**[56:25]** When LSTMs and GRUs were trained on such architectures for machine translation, they found an unsolvable problem. It works for short sentences like "hello world", but doesn't scale up. The issue is the dimension of Z: if Z is too small, it cannot fit enough meaning, so it works for short sentences but breaks down for long ones. If you make Z longer, training becomes harder because hidden states or decoder inputs become longer, quadratically increasing weights and requiring more data and compute than available. This cannot be solved within this architecture. If you graph quality against sequence length, it's very good for short sentences but drops sharply for longer ones. Ideally, it would drop gracefully and still work for longer sequences. Attention mechanisms for encoder-decoder recurrent networks were supposed to fix this, and this concept remains relevant.

**[1:01:49]** The problem with Z is that it's a single vector for the whole input. We need to change that—transformers also don't use a single vector. When translating, specific words are more important at certain steps (for example, "world" should be more important when translating "mir"), but a single vector cannot express that. The first step is to remove the assumption that everything must be in one vector.

**[1:03:07]** In encoder-decoder with attention, the input is still processed by a bidirectional recurrent network, but it produces outputs for every input token, giving vectors Z1, Z2, Z3. You cannot simply concatenate them, as that would make Z too long. You want one vector of manageable size as input at each decoder step. The attention mechanism combines them: a small attention network takes a Z vector and the current decoder hidden state as input, producing a score that indicates the token's importance at that step. This is done for every Z, yielding scores a1, a2, a3. These scores are passed through a softmax to convert them into probabilities, forming a convex combination.

**[1:07:49]** I use softmax not only at the output but also to convert any set of numbers into a convex combination that sums to 1, yielding attention weights $\alpha_i$ in $[0,1]$ summing to 1. These are the coefficients for a linear combination: $U_t = \sum_i \alpha_i Z_i$, where $U_t$ is the input to the decoder at time step $t$, a weighted sum of all encoder token representations with weights determined by the separate attention network.

**[1:09:17]** The intuition is that at each decoder step, we want to indicate which token we are currently translating. For instance, at step 3 when producing "world", the weight for the token "world" should be high, in context. Crucially, there is no labeling in the dataset that says which token is being translated at each step; the dataset only consists of parallel sentences. After training, the attention network learns to align without direct supervision. The attention network is tiny—about 2% of the total weights—yet it drives the improvement, as seen in the difference between the red and purple curves. This illustrates a general principle: if you structurally give the network a component with the potential ability to do the desired job, even without any direct training signals for that component, it often learns to do it correctly.

**[1:13:25]** In late 2014, Bahdanau et al. introduced this attention mechanism: a small network takes the current decoder state and an encoder token representation, produces a score, and a softmax gives the attention weights. It indeed trains to align.

**[1:14:19]** A common feature of attention mechanisms is that the resulting weights are easily interpretable. In a French-to-English translation example, the attention matrix is mostly diagonal—word-by-word translation—but with notable exceptions. "La destruction" maps to "destruction" (two words to one), with high attention on both input words while writing the single output word. "Armes chimiques" becomes "chemical weapons": in French the adjective follows the noun, in English it is the opposite, so the attention weights are off-diagonal, showing the swapped order.

**[1:15:59]** In a simple reversal task, the attention network learns a reverse diagonal, allowing the model to reverse a sequence without having to memorize the entire input in the encoder's hidden state. Without attention, reversing a long sequence would be very difficult if the hidden state lacks sufficient capacity. Similarly, in a sorting task, at each decoding step the attention attends to the current smallest value in the input—first step to the position of 1, then to 3, then 4, and so on—demonstrating that the mechanism learns to pick the correct element.

**[1:19:05]** This attention mechanism brought many benefits: it handles word order better and can even tackle structured outputs like syntax trees by simply representing the tree as a string and treating it as the target language. In 2016, Google published a paper detailing their neural machine translation system, which used the same encoder–decoder with attention, confirming its practical power.

**[1:21:03]** And by the way, my personal experience was that around 2015, 2016, when they switched from whatever they had before to this kind of architectures, Google Translate actually became much better. I had a side job at the time translating research papers from Russian to English. Before about 2016, I tried to use Google Translate, but it was completely hopeless; you would spend much more time fixing its results than typing from scratch. In 2015-2016, there was a phase transition. Suddenly, sure, it was still bad and needed editing—you still need to edit translations, even from the latest versions of GPT—but now it was more efficient to first do a pass with Google Translate and then fix the mistakes than to do everything yourself. This was the moment when machine translation actually started doing useful work for me.

**[1:22:38]** The last point here is that when I'm talking about encoder-decoder architectures, usually I talk about the same kind of architecture in the encoder and the decoder. For machine translation we had a recurrent encoder reading text and a recurrent decoder writing text, but it doesn't have to be that way. You can have encoder-decoder architectures where the input has one modality, one kind of network, and the output is a completely different kind of network and modality. I don't even think this counts as multimodal architectures because, although they are multimodal, the two modalities are separate—all you need from the encoder is a vector representation, which you plug into the decoder. For example, I mentioned the captioning problem. As it was in 2015, the encoder was a GoogLeNet and the decoder was an LSTM, and it became much better when people added an attention mechanism.

**[1:24:08]** And again, this is also important for what will come later. Notice that you can do the exact same kind of attention highlighting specific parts of the input, even if your input is not text or a sequence. If you have a picture, for example, the only difference is that we don't compress the whole picture to a single feature vector like in a straightforward encoder-decoder. We have the same CNN, but we cut it off a little before the end, so that we still have some geometry left. For instance, if the input is $256 \times 256$, we stop the feature extraction when we have a $14 \times 14$ feature map. Now we have these "pixels"—elements of the feature map vectors—and we can do attention over these vectors. So an attention network gives us coefficients to combine these $14 \times 14$ different vectors. Another nice thing is that it gives you the actual attention weights; you can look at them and interpret them. We will kind of see that in transformers too, but it will be less clear and more complicated there. Here, it's very clear and straightforward: you can just see what the network is looking at as it writes each piece of the output. So, "a woman is throwing a frisbee in the park." When writing "woman," it looks at the people; "throwing," it concentrates on the throwing action; "frisbee," on the frisbee; and when writing "park," it looks at the background. That's just perfect.

**[1:27:53]** Okay, so on to the Transformers. Transformers appeared in 2017. Let me start with a brief historical remark. I am pretty sure the authors of the "Attention Is All You Need" paper didn't actually understand what they were doing. The paper is not that ambitious; its original results showed a more efficient way to achieve approximately the same results. But since then, the whole field of machine learning switched to transformers, and much of the rest of our class will be built on them. The main positive qualities that the transformer had, which the original paper couldn't notice from its experiments, are two things. One, it proved to be very, very general: the transformer is very good at noticing internal correlations within complicated data. It doesn't really matter whether it's text, images, or whatever—it just works with sequences of vectors and doesn't care where they come from. The even more important thing is that transformers proved to be extremely scalable. You can take a transformer, scale it up, and it works better. You can scale it further up without changing anything inside. Modern transformers are slightly different from the original but mostly the same, and still you scale it up and it works better and better, and it never saturates. With large language models, we keep going from tens of millions to hundreds of millions, to billions, to hundreds of billions, to now trillions of parameters, and they just keep getting better. This had never happened before. You can't scale LSTMs in the same way—maybe you could with enough compute, but the complexity grows too fast, or they saturate and stop improving. In the transformer, it all came together.

**[1:50:03]** What is the transformer? I will go through the slides first because the basic structure is similar to what we just discussed, but the main core will be the self-attention mechanism, which is completely new and I will discuss in detail. Here is the structure of the original transformer: the general structure is very straightforward and similar to recurrent encoder-decoder with attention. It's an encoder-decoder architecture for machine translation, with an encoder of six identical layers and a decoder of six identical layers. The encoder receives text in one language, the decoder produces text in another. The input to the actual transformer layers is not just a sequence of tokens. It had been very common in NLP to convert one-hot representations of words (tokens) to continuous representations called embeddings. If you have a large vocabulary, you first convert them to dense vectors. There is a whole line of work on this (word2vec, GloVe, fastText), but here the embeddings are straightforward. There is just one very interesting technical thing...

**[1:53:02]** The embedding layer is a matrix of vectors: for each input token we look up its vector and place it in the token’s position. Crucially, this is not an external representation like word2vec; it is an embedding layer trained jointly with the rest of the network. After embedding, the input becomes a sequence of vectors. The entire transformer simply rewrites sequences of vectors into sequences of vectors. Each encoder layer takes a sequence of vectors as input and produces an output sequence of the same size. This rewriting happens multiple times (six here), yielding a vector for every input token. After all encoding steps, each vector no longer represents just the token but the token in the context of all other tokens across the whole sequence. Thus, by the top of the encoder, we have semantically rich representations of the input tokens.

**[1:54:40]** The decoder is a language model, producing output tokens one by one autoregressively: its input is the output history so far, and its output is the next token. You must run the decoder as many times as the number of tokens to produce. This autoregressive constraint is something modern language models work around (e.g., speculative decoding), but by default it is token-by-token. The encoder outputs are used in every decoder layer at every step. The high-level structure is similar to what we saw earlier: attention is not a separate network; it is hidden inside the encoder and decoder layers.

**[1:56:50]** Looking inside an encoder layer, it consists of a self-attention layer, then layer normalization, then a feed-forward (fully connected) layer, and another layer normalization. The crucial part we will discuss in detail is the self-attention layer at the start. The rest uses familiar components: a residual connection wraps around the self-attention layer and feeds into the layer normalization. Layer norm (discussed with Alex) is similar to batch norm but normalizes across the outputs of the current layer, not across a mini-batch. It smooths the loss landscape and keeps output magnitudes under control. Because transformers are large, fitting only one instance in memory, batch norm is infeasible, so layer norm is used instead. The feed-forward layer, though simple, accounts for a large fraction of the model’s weights and simply rearranges and mixes features independently for each vector (applied to each Z’ individually).

**[2:00:20]** The decoder layer has the same components (self-attention, feed-forward, layer norms) plus an encoder-decoder attention layer, which is where the encoder outputs are incorporated (we will explain how later). The self-attention in the decoder is masked, a detail we will cover.

**[2:00:54]** After the decoder, a linear layer followed by softmax yields token probabilities, from which the next token is sampled. This is essentially logistic regression at the end, tying everything together.

**[2:01:20]** The overall structure should be familiar except for the self-attention mechanism. So what is self-attention, and where does it come from?

**[2:01:47]** To discuss self-attention, we need to step back to information retrieval. How does search work with neural networks? We have queries and documents. Documents are passed through one encoder, queries through another (possibly different, e.g., for images), mapping them into a shared latent space. The system is trained so that relevant documents are close to the query in this space. Retrieval then reduces to finding nearest neighbors, using the dot product as the similarity measure. The core intuition is that different modalities are mapped to the same latent space, and similarity is a simple dot product.

**[2:06:57]** Self-attention draws on this intuition, but applies it to a single set of vectors that serve as both queries and documents. Here is how it works.

**[2:07:40]** So we begin with a set of vectors. Every layer of the transformer receives a sequence of vectors as input: $x_1, x_2, \dots, x_n$.

**[2:08:12]** To motivate self-attention, consider an information retrieval analogy. In retrieval, a query is matched against document representations called keys. We can think of each input vector $x_i$ as being mapped to a key, while a given query (derived from one of the inputs) is mapped into the same space. The similarity between query and key determines attention.

**[2:09:03]** Given $x_1$, we produce a query vector $q_1 = W_Q x_1$. From all inputs we produce key vectors $k_i = W_K x_i$ (for $i = 1,\dots,n$) and value vectors $v_i = W_V x_i$. Queries and keys live in the same latent space of dimension $d$, so their similarity is measured by the dot product.

**[2:10:59]** For query $q_1$, we compute affinity scores $a_{1j} = q_1 \cdot k_j$ for each key $k_j$. These scores are scaled by $1/\sqrt{d}$ and passed through a softmax to yield attention weights $\alpha_{1j}$, which sum to 1.

**[2:12:39]** The attention weights are used to form a convex combination of the value vectors. The output for position $1$ is $z_1 = \sum_j \alpha_{1j} v_j$.

**[2:14:26]** The same procedure is repeated for every position: from $x_2$ we obtain $q_2$ and so on, yielding $z_2 = \sum_j \alpha_{2j} v_j$, and in general $z_i$ for each input $x_i$.

**[2:15:27]** In matrix form the computation is compact. Let $X$ be the matrix of input vectors. Then $Q = X W_Q^\top$, $K = X W_K^\top$, $V = X W_V^\top$ (the exact ordering of multiplication depends on the convention). The full self-attention operation is

$$ \text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right) V, $$

where the softmax is applied row-wise. This is the formula from the original 'Attention Is All You Need' paper.

**[2:17:46]** Regarding dimensions: the input $X$ is in $\mathbb{R}^D$, while queries and keys must live in the same smaller space $\mathbb{R}^d$ in order to compute dot products. Thus $W_Q$ and $W_K$ are $d \times D$ matrices. Values can formally have a different dimension $d'$ (the matrix $W_V$ is $d' \times D$), though in practice $d' = d$ is typical.

**[2:19:24]** The scaling by $1/\sqrt{d}$ prevents the dot products from growing too large. If we regard the entries of $q_i$ and $k_j$ as random variables with zero mean and unit variance, the dot product $q_i \cdot k_j$ is a sum of $d$ such products and has variance proportional to $d$, hence a typical magnitude of $\sqrt{d}$. Without scaling, the softmax inputs would be large in magnitude, leading to saturated attention weights. Dividing by $\sqrt{d}$ keeps the variance of the pre-softmax logits at a manageable level.

**[2:22:07]** Dot products of around $\pm 8$ cause the softmax output to approach a one-hot vector. Since we need smoother attention weights, we rescale by $\sqrt{d}$ to bring the values back to approximately one. This is the purpose of the scaling factor.

**[2:22:33]** Here we see the main computational problem of transformers. To compute attention, you need an $n \times n$ matrix of pairwise interactions. This leads to quadratic complexity in the input sequence length $n$. This is the main bottleneck: transformers cannot scale to long sequences without tricks. Many techniques have been developed to address this, forming a large field of research.

**[2:23:50]** A few years ago, large language model developers boasted about context sizes—128,000 tokens, 512,000 tokens, or a million-token context window. Achieving a million-token context is not trivial: the complexity scales quadratically, so a million squared is prohibitively large. You cannot compute the full $n \times n$ matrix directly; you need tricks. For example, Claude has a separate Opus model with a one-million-token context, which is more expensive and complex than the standard version. Context length remains a difficult problem for transformers.

**[2:25:20]** From a geometric perspective, we take the input vectors $x$ in a high-dimensional space and project them to a much smaller space in two different ways to obtain queries and keys. Mathematically, this means finding two projections of the same dimension for queries and keys—two ways of looking at the set of vectors $x$. There is also a third projection for the values, which can have a different dimension.

**[2:26:34]** This raises the same question as yesterday: if all we do with the vectors is compress them into queries, keys, and values (e.g., from a large dimension $D$ of 256 or 512 down to a small $d$ of 64), why do we need the long vectors at all? The answer is that what I have drawn is just one attention head. In practice, transformers use multiple attention heads, each with its own $W^Q$, $W^K$, and $W^V$ matrices, producing their own view of the input and their own output $z_i$. So there is effectively another index over heads.

**[2:27:59]** Let us walk through the self-attention picture again. The input is a set of vectors. Each vector is multiplied by three matrices: $W^Q$ gives the query, $W^K$ gives the key, and $W^V$ gives the value. Queries and keys live in the same latent space. We compute the dot product between each query and every key—not cosine similarity, because we do not normalize by norm—to obtain affinities. We then rescale by $\frac{1}{\sqrt{d}}$ (where $d$ is the dimension of the key vector), apply softmax to get convex weights, and finally form a convex combination of the value vectors using these weights.

**[2:29:47]** Notice that every query looks at all input tokens, including itself. This is a crucial property that makes transformers powerful. For example, if we have $x_1, x_2, \dots, x_L$ and we want $x_1$ to relate to $x_k$, a recurrent network would require step-by-step propagation through intermediate tokens; there is no path that jumps directly. Even with an LSTM's memory cell and constant error carousel, information must still flow step by step, and much can happen along the way. A transformer, however, jumps directly from $x_1$ to $x_k$ in one step. In fact, it jumps from every $i$ to every $j$ on every layer. This is a major advantage, but the cost is quadratic complexity. Recurrent networks have linear complexity in input size (each step has constant cost), while transformers are quadratic. This is a huge difference, but transformers can freely capture long-range relations because they see the entire sequence at once on every layer.

**[2:34:31]** The length of the value vector determines the output dimension, because the output is a linear combination of value vectors; consequently, the dimension of $Z$ equals the dimension of $V$. If we instead used the full model dimension $D$ for each head’s output, combining many such $D$-sized $Z$’s and then compressing them back to a single $D$-sized output would require too many parameters and be computationally inefficient. So using a smaller value dimension is purely an efficiency optimization. Multi‑head attention itself remains essential for expressive power.

**[2:35:51]** The multi‑head attention layer consists of several heads (head 1, head 2, …, head $H$). Each head produces its own matrix $Z$ (from the boxed attention formula), and these must be combined. After combination, the output of the layer should have the same shape as the input $X$—this is standard practice so that identical layers can be stacked. The final $Z$ (top‑right in the diagram) is therefore of size $L \times D$, exactly like $X$. The intermediate representations, however, are much larger. Let $X$ be of shape $L \times D$ ($L$ vectors of dimension $D$). Each head $i$ computes $Z_i$ of size $L \times d$, where $d$ is smaller than $D$. Concatenating all $H$ heads yields a matrix of size $L \times (H \cdot d)$, which is typically much larger than $D$. We then multiply this concatenated matrix by a learned weight matrix (a linear layer) that projects it back to $L \times D$, giving the final $Z$.

**[2:39:47]** The intuition for multi‑head attention is twofold. First, we need variety among the $Z_i$—not merely different linear combinations of the same vectors, but different projections of the inputs, which increases expressive power. Second, if the per‑head dimension $d$ were equal to the model dimension $D$, the concatenated matrix would be $L \times (H \cdot D)$, far too large to train efficiently. Multi‑head attention thus offers richer representations while keeping the architecture computationally tractable. In summary, a single attention head is replicated $H$ times, all heads run in parallel, their outputs are concatenated and projected, and the result is the $Z$ that defines the self‑attention layer of the encoder.

**[2:41:38]** The decoder introduces two additional concepts: masked self‑attention and encoder‑decoder attention.

**[2:42:07]** Masked self‑attention is a purely efficiency‑driven mechanism. When the decoder generates tokens one by one, it applies ordinary self‑attention to the current prefix. During training, however, we have the full target sequence. We can view this target—say, seven tokens—as seven separate training samples: predict token₂ from token₁, token₃ from token₁ .. ₂, and so on. Running the decoder many times would be inefficient. Instead, we feed the entire target sequence at once and apply a causal mask to self‑attention: at position $t$, only positions $1$ through $t-1$ are visible. This is implemented by zeroing the attention weights for future positions. The underlying computation remains unchanged; the mask merely enforces the constraint that each prediction depends only on the prefix.

**[2:46:31]** Encoder‑decoder attention uses exactly the same self‑attention mechanism. The only difference is that the queries come from the decoder’s previous layer ($Q$ is obtained by multiplying the decoder input by $W^Q$), while the keys and values come from the encoder’s output ($K$ and $V$ are derived from the encoder representations). This allows every decoder position to attend to the entire encoded source.

**[2:48:05]** Keys and values are produced from the encoder representations by multiplying with learned weight matrices $W_K$ and $W_V$, exactly as before. The only difference is that we do not produce queries, keys, and values all from the same $X$: queries $Q$ come from the decoder's input, while $K$ and $V$ come from the encoder output (the condition). This does not break anything. Previously the attention matrix was square ($L \times L$), but now it is not quadratic because the number of queries and keys can differ; the sequences need not be the same length. We never assumed they were: for each query we multiply with all keys, giving as many attention weights as there are keys. The number of keys must match the number of values so that we can sum values with those weights, but the queries can be entirely separate. For example, in object detection with transformers, queries, keys, and values come from very different sources. Having queries from one source and keys/values from another is a common transformer design, dating back to the original transformer decoder, which uses encoder outputs in exactly this way.

**[2:50:17]** That is the essential transformer architecture, arguably the most important architecture today. It is a lot to absorb, but you will gain understanding by revisiting the diagrams and especially by implementing it yourself. It is not hard, just abstract: value vectors are merely trained projections of input token representations, and it is hard to give deeper intuition. Interestingly, after training, attention heads often perform very interpretable, intuitive operations. We may see examples later.

**[2:51:45]** As a trivial example, a single self‑attention layer with one head can learn to output a matching key; its attention matrix simply looks at the correct position. Another example shows that the attention matrix need not be a permutation matrix. Often they look like permutation matrices, but they can be more complex, for instance an orientation matrix where tokens are split into groups (e.g., sizes 3, 3, 1, 3) and queries attend uniformly to all tokens within their group. Thus, widely distributed attention patterns are possible.

**[2:54:41]** Although tokenization is less relevant for images, it is worth mentioning because it connects to coding theory. The fundamental question is: where does the token dictionary come from? Treating each word as a token makes the vocabulary too large: grammatical variants and typos must remain separate tokens, otherwise we lose information by discarding unknown words, and including all misspelled forms would yield millions of entries. Using characters as tokens gives a tiny vocabulary (a few hundred symbols), but sequences become too long given a practical context limit of around one million tokens—a million characters cover far less text than a million words. We need an intermediate granularity.

**[2:57:59]** Byte‑pair encoding (BPE), essentially Huffman coding, solves this elegantly. Start with a dataset of word frequencies and treat each character as a token. Repeatedly find the most frequent adjacent pair of existing tokens, create a new token representing that pair, and replace every occurrence of the pair with the new token. Update the token counts and repeat. For example, if the pair “at” is most frequent, introduce a new symbol Z for “at”; “a” and “t” remain in the vocabulary because they appear separately, but words become shorter. This process gradually builds a subword vocabulary that balances sequence length and dictionary size. We then continue merging the next most frequent pair, and so on.

**[3:00:53]** So, very simple algorithm, very straightforward. And the beautiful part is that you can stop it at any time. You can say, for example, let's say I have a capacity for a vocabulary of size 100,000. That's way too much to have just characters and way too little to have complete words. So I just run this, adding tokens one by one, until I reach exactly 100,000 and stop. If you do it, you will see that first it will find common, frequent parts of words like -ed (because it's at the end of every verb in past tense) or -tion (because it's at the end of many nouns), and so on. Then common words will be single tokens, uncommon words will be multiple tokens, and that's okay. That's how tokenization works.

**[3:02:03]** And one more interesting remark about transformers: because they are so cool and have this wonderful ability to go from any token to any token in one step, this is their biggest strength. But it comes with a drawback: transformers lose word order. In recurrent networks, there is a very meaningful sense of adjacent and far-away tokens—adjacent tokens take one step, far tokens many steps—so you don't need to remind the network of word order. Transformers, however, are just a matrix of attention weights; a generic matrix doesn't care if rows are adjacent or far apart. So transformers don't care about word order, and that's a bad thing. We do want to keep the order. So in practice, we add special vectors called positional encodings to the token embeddings, whose only job is to encode the token's position in the sequence. Let me briefly hint at the main idea: you could have a one-hot representation for position 1, 2, 3, etc., but you want these positional encodings to support arithmetic, to capture distances between tokens. Specifically, you want $e_i - e_j$ to be similar to $e_{i+k} - e_{j+k}$, so that if two positions are the same offset apart, their encoding difference is consistent across the sequence. In the original transformer, they used a positional counting system akin to binary numbers. Looking at binary representations from 0 to 15: the last digit oscillates 0,1,0,1; the next with twice the period (0011,0011); then four zeros and four ones, and so on. You can create a soft version using sine waves of different frequencies in the encoding: start with high-frequency sine waves that oscillate a lot, then reduce the frequency. This gives a positional counting system with the necessary properties. That was the original sinusoidal positional encoding. The current approach, mostly used today, is called RoPE (rotary positional encodings). Rotary means something is rotating. In RoPE, you take the vector $x$ and break it into pairs of consecutive numbers (two-dimensional vectors). So $x_1, x_2$, then $x_{11}, x_{12}$, etc. Each 2D part can be rotated by various angles, because a vector of two numbers is a plane vector you can rotate. Rotary encodings multiply each 2D subvector by rotation matrices, with positions encoded as coefficients. For example, $\begin{pmatrix} \cos k\theta & \sin k\theta \\ -\sin k\theta & \cos k\theta \end{pmatrix}$. There is a basic angle $\theta$, and you rotate by multiples $k\theta$. This gives perfect arithmetic: rotating by $k\theta$ then $L\theta$ is the same as $(k+L)\theta$. So this kind of positional encoding has nice arithmetic properties. I have illustrations here: the sinusoidal positional encoding shows that the dot product between two vectors depends only on the offset $i-j$, which is the desired property. Rotary positional encodings also exhibit a diagonal structure in the dot product matrix, meaning the same offset yields the same dot product. I also have an illustration for why the scaling by $\sqrt{d}$ is necessary: if you don't scale, after softmax you get closer to one-hot representations and lose entropy.
